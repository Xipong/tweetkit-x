# X Research — поисковый MCP для ChatGPT

Отдельный read-only сервер в форке `Xipong/tweetkit-x`. **Запускать `tweetkit-research`, НЕ `tweetkit-mcp`**: старая библиотека, CLI и исходный MCP сохранены для совместимости и по-прежнему умеют писать в аккаунт. Новый сервер их инструменты не регистрирует и допускает только явно перечисленные операции чтения X.

21 инструмент по умолчанию; 25 с `--personal`. Без Chromium/Playwright, без платного X API. Авторизация X — локальный файл cookies. Дополнительный `--impersonate` использует curl_cffi с профилем TLS Chrome, но не запускает браузер. Это не обещание обхода любой защиты: X может отклонить сессию, урезать выдачу или поменять приватный API.

## Установка на Windows

Нужны Python 3.10+ и Git. В PowerShell, для версии из PR:

```powershell
git clone https://github.com/Xipong/tweetkit-x.git
cd tweetkit-x
git switch feat/chatgpt-research
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[research,browser]"
```

После слияния PR можно использовать `main`. SDK намеренно ограничен `mcp>=1.28,<2`: этот сервер использует поддерживаемый v1 FastMCP, не API v2.

Один раз войдите в X обычным браузером. Сохраните **локально**, не в чате, файл с одной строкой:

```text
auth_token=ВАШ_ТОКЕН; ct0=ВАШ_CT0
```

Файл лучше держать вне репозитория, например `%USERPROFILE%\.config\tweetkit\cookie.txt`. Это пароль к сессии, а не публичный API-ключ. Ограничьте доступ к файлу своим пользователем; не коммитьте его и не отправляйте HAR в чат. Указать нестандартный путь можно так:

```powershell
$env:TWEETKIT_COOKIE_FILE = "$HOME\.config\tweetkit\cookie.txt"
.\.venv\Scripts\python.exe -m tweetkit_x.research_server --help
```

На Linux/WSL: `python3 -m venv .venv`, `.venv/bin/python -m pip install -e '.[research,browser]'`; для файла cookies — `chmod 600`. Существующий локальный импорт `tweetkit import --file ...` также поддерживается. Не передавайте cookie аргументом командной строки или инструментом модели.

## Подключение к ChatGPT

### Предпочтительно: приватный Secure MCP Tunnel, stdio

Создайте туннель по актуальной официальной инструкции OpenAI и настройте его на локальный процесс:

- executable: **полный путь** к `.venv\Scripts\python.exe`;
- arguments: `-m tweetkit_x.research_server --transport stdio --impersonate`;
- environment: `TWEETKIT_COOKIE_FILE` с локальным путём.

Для WSL пути должны быть Linux-путями внутри WSL. Рабочий процесс и туннель должны оставаться запущенными. `stdio` не предназначен для вставки в поле URL и ничего полезного не печатает при обычном ручном запуске.

В форме ChatGPT: название `X Research`, подключение **Туннель**, созданный туннель. Для изменения списка инструментов после обновления сервера обновите/пересканируйте плагин.

Настройки и права туннелей зависят от доступности функции в аккаунте. Сервер не создаёт туннель и не настраивает OpenAI Platform самостоятельно. Не нужен платный X API; отдельные требования OpenAI к туннелю проверяйте в его интерфейсе.

Официальная инструкция: https://developers.openai.com/plugins/deploy/connect-chatgpt

### Альтернатива: собственный HTTPS-адрес, Streamable HTTP

Встроенного OAuth-сервера нет. Для личного одно-пользовательского развёртывания предусмотрен **секретный адрес с 256-битным случайным ключом**. Любой обладатель полного адреса получает доступ к инструментам от вашей сессии X. Это capability URL, не полноценный OAuth и не изоляция нескольких пользователей. Предпочтительнее приватный туннель; для общего сервиса нужен внешний проверенный OAuth/gateway.

```powershell
$env:TWEETKIT_MCP_PATH_KEY = (& .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))")
.\.venv\Scripts\python.exe -m tweetkit_x.research_server `
  --transport streamable-http --host 127.0.0.1 --port 8765 `
  --public-host x-research.example.com --impersonate
```

Замените `x-research.example.com` своим реальным HTTPS-доменом. Ваш HTTPS reverse proxy / туннель должен пересылать запросы на `127.0.0.1:8765`, **сохраняя путь и Host**, без кэширования MCP-ответов и без записи секретного пути в access-логи. Внешний TLS настраивается отдельно; сам процесс обслуживает локальный HTTP. Для контейнера нужен `--host 0.0.0.0` внутри него, но публикуйте порт хоста только на loopback за HTTPS proxy.

В форме ChatGPT:

```text
Название: X Research
Подключение: URL-адрес сервера
URL: https://x-research.example.com/<ЗНАЧЕНИЕ_TWEETKIT_MCP_PATH_KEY>/mcp
Аутентификация: Без аутентификации
```

«Без аутентификации» здесь означает отсутствие OAuth-handshake; полный URL остаётся секретом. Не отправляйте его в публичные чаты. Перегенерация ключа отзывает старый адрес и требует обновления коннектора. Без ключа публичное подключение/публичный bind отвергаются. При отсутствии `--public-host` разрешены только локальные Host. Неверный путь возвращает 404 без подсказки ключа. Access-логи встроенного uvicorn отключены, но за логи внешнего proxy отвечает владелец.

Используйте **один worker / один процесс**: continuation-буфер находится в памяти процесса. После перезапуска старые курсоры истекают. Не подключайте открытый `/mcp` без секретного пути к публичному прокси: защита Host не заменяет авторизацию, особенно если proxy переписывает Host на localhost.

## Инструменты

| Группа | Инструменты | Возможности |
|---|---|---|
| Совместимость с коннектором | `search`, `fetch` | Строгие схемы результатов с ID, заголовком, полным доступным текстом и канонической ссылкой; structuredContent плюс текстовый JSON |
| Основной поиск | `search_x`, `search_many` | Top / Latest / Media, настоящий поиск X, до 8 вариантов запроса, дедупликация с происхождением результата, продолжение страниц |
| Поиск по направлениям | `search_users`, `search_user_posts`, `search_quotes`, `search_conversation` | Аккаунты, индексированная история автора, упоминания/возможные цитаты поста, индекс корневого обсуждения |
| Чтение | `get_tweet`, `get_tweets`, `get_thread`, `get_replies` | Пост/пачка до 10, авторская цепочка даже с середины, обсуждение с отдельными курсорами ветвей |
| Авторы и связи | `get_user_profile`, `get_user_tweets`, `get_followers`, `get_following`, `get_likers`, `get_retweeters` | Профили, ленты, видимые связи и участники распространения поста, с пагинацией |
| Медиа | `get_media`, `get_image` | URL/alt/размеры/варианты видео; реальные картинки в MCP ImageContent, а не только их описание |
| Диагностика | `status` | Настроены ли cookies локально и последние наблюдавшиеся квоты; не раскрывает секреты |

Дополнительные **четыре** инструмента при явном `--personal`: `get_home_timeline`, `get_bookmarks`, `get_user_likes`, `get_notifications`. Они читают личные данные подключённого аккаунта. Этот флаг не включает никаких публикаций или изменений аккаунта. Лайки чужих пользователей и полная лента событий уведомлений не гарантируются.

Не урезан основной исследовательский набор ради небольшого числа инструментов. Лишнее убрано именно из управления аккаунтом: публикации, удаления, лайки, подписки, импорт cookies и чтение локальных файлов моделью здесь отсутствуют.

## Как искать глубоко, а не повторять первую страницу

`search_x` сохраняет порядок выдачи Top. Поиск лексический, не семантический: нужны разные формулировки, точные фразы, имена, языки, даты. Например:

```json
{
  "queries": [
    "\"Qwen\" \"shooter\"",
    "\"Qwen\" \"FPS\" \"cost\"",
    "\"Qwen\" \"6 hours\"",
    "\"Квен\" \"шутер\""
  ],
  "product": "Top",
  "limit_per_query": 40,
  "max_pages_per_query": 2
}
```

У `search_many` каждый результат сохраняет `matched_queries`. В отчёте каждого запроса есть его `next_cursor`, ошибки и статус. Продолжать отдельный запрос нужно **`search_x` с тем же query/product** и этим курсором. `search_user_posts` ограничивает запрос `from:...`; `OR`-часть группируется в скобки. Для обхода UserTweets с ответами надёжнее дополнительно использовать авторский поиск: сама лента не обещает весь архив ответов.

Для первичного поиска доступны страницы до 200 постов и до 10 X-запросов на вызов, по умолчанию 50/3. `search_many`: до 8 вариантов, 100 результатов и 3 страницы на вариант. Есть мягкий временной бюджет около 40–45 секунд, проверяемый между сетевыми запросами; один начатый запрос/инициализация транспорта могут увеличить фактическое время. Нормальные таймауты/лимиты возвращаются явно, а не превращаются в пустую «успешную» выдачу.

Курсор хранит не только upstream cursor, но и неотданный хвост страницы: `limit=10` не выбрасывает оставшиеся 40 результатов X. Он привязан к операции/запросу/фильтрам, действует 15 минут, может вытесняться ограниченным буфером 32 MiB / 256 состояний. Применение к другому запросу, истечение и перезапуск сообщаются явно. При очень больших выгрузках дополнительно дедуплицируйте ID сами: окно ID в одном курсоре ограничено.

Посты сохраняют полный доступный note-текст, автора, время, conversation_id, родителя, метрики, ссылки и медиа. Цитаты и репосты вложены в исходный результат, не выданы за самостоятельные попадания поиска. Статья возвращается с флагом `preview_only`, если X дал лишь превью. Отсутствующий/скрытый пост не объявляется доказанно удалённым.

`get_thread` поднимается по родителям одного автора, затем исследует его продолжения, прежде чем тратить все запросы на тысячи чужих ответов. Другие авторы остаются в `context_posts`. `max_posts` ограничивает общий пул постов, включая контекст, а не только авторскую цепочку. Ответ содержит `missing_parent_ids`, `continuations`, `truncated`, ошибки и `complete_archive=false`. Продолжения указывают focal ID и сырой cursor: для них используйте `get_replies(reference=focal_id, branch_cursor=cursor)`, а при `cursor=null` — обычный `get_replies`. Сам `get_thread` не обещает автоматический обход всех скрытых ответов/ветвей и не имеет общего continuation token.

`search_quotes` — приблизительный поиск `url:<ID>`, не полная специальная лента цитат. Проверяйте `quoted_post_id`. `search_conversation` требует **корневой** conversation_id; индекс может пропускать ответы, поэтому сверяйтесь с `get_replies`. Изображения загружаются только с `pbs.twimg.com`, без cookies, без редиректов, максимум 5 MiB; возвращается MCP ImageContent. Реальное отображение зависит от поддержки клиентом. Видео — ссылки и метаданные, не распознавание речи и не покадровый просмотр.

## Надёжность и безопасность

Cookies остаются в процессе сервера. Сетевой слой разрешает только перечисленные операции чтения; POST используется только для двух читающих home-timeline endpoints. У всех инструментов readOnlyHint=true, destructiveHint=false. Аннотация дополняет, а не заменяет allowlist.

На 429/коды ограничения возвращаются retry_after/диагностика; автоматического бесконечного ретрая нет. Временные квоты хранятся по endpoint. Параллельные MCP-вызовы сериализованы для одной X-сессии. Сырые исключения requests, содержимое HTTP-ошибок и пути файлов модели не передаются.

Защита от prompt injection не абсолютна. Инструкция серверу требует считать посты/биографии/alt-текст недоверенными данными и цитировать первоисточник, а не исполнять найденные команды. У read-only процесса всё равно есть доступ к сессии: не подключайте его к недоверенным клиентам, не выдавайте этот URL другим людям.

X может менять приватные query ID и feature flags. Их можно обновить **локальными** JSON-файлами без добавления сырого GraphQL-инструмента модели:

```text
TWEETKIT_QUERY_IDS_FILE=/private/read-query-ids.json
TWEETKIT_FEATURES_FILE=/private/feature-flags.json
```

Первый файл — объект `{ "SearchTimeline": "АКТУАЛЬНЫЙ_QUERY_ID" }` только для разрешённых read-операций. Второй — объект `{ "имя_флага": true }`. Значения нужно брать из актуальной X-сессии/исходников, а не угадывать. Никакого автоматического обновления query ID или обхода ограничений нет. После изменения файлов перезапустите сервер; старые курсоры истекут.

## Проверка после установки

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[research,test]"
.\.venv\Scripts\python.exe -m pytest -q
```

Unit-тесты используют синтетические ответы X. Отдельный модуль проверяет настоящий MCP SDK: discovery, схемы search/fetch, Streamable HTTP initialize/tools/list/tools/call, isError, read-only annotations и ImageContent. Без установленного MCP этот модуль явно пропускается; CI устанавливает зависимости и должен исполнять его. Ни один тест не публикует твиты и не использует реальную сессию.

После подключения в ChatGPT проверьте по порядку: `status`, один конкретный пост через `get_tweet`, поиск Top/Latest, продолжение `next_cursor`, известный тред из нескольких постов, картинку через `get_image`. **Офлайн-тесты не доказывают работоспособность текущих приватных endpoint X или принятие коннектора вашим аккаунтом ChatGPT.** При сбое сохраняйте код ошибки без cookies/URL-ключа; он покажет, какой слой нужно чинить.

Пользоваться неофициальным API следует с учётом правил и ограничений X; безопаснее не экспериментировать на ценном основном аккаунте.
